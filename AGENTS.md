# AGENTS.md: libshieldnet for LLMs and coding agents

This file is for AI assistants and coding agents that build **with** this library
or change the library itself. People should start with
`README.md`, the Overview page of the documentation site. The same guidance,
with the whole documentation in one file, is on that site as `llms.txt` and
`llms-full.txt`.

## What the library is

The portable C11 implementation of ShieldNet, the encrypted protocol between
ShieldLED controllers and LED devices, in both roles: the **device** (LED
firmware such as the ESP32 boards) and the **client** (the controlling
application). One dependency, libsodium 1.0.19 or newer. Platform code sits
behind the headers in `port/`.

A desktop application should use
[libshieldnet-client](https://github.com/shieldled/libshieldnet-client), which
wraps the client role in a blocking, thread-safe API with discovery.

## Where the facts are

- The public headers, `include/shieldnet/*.h` and `port/*.h`, document every
  call where it is declared. Entry points:
  - device: `sn_device.h` (`sn_device_init_kdev`, admission, sessions),
    `sn_agent_dispatch.h` (`sn_agent_init`, `sn_agent_step`, `sn_agent_end`: the
    device's message loop), `port/shieldnet_device.h`
    (`shieldnet_device_ops_t`, the callbacks a device implements);
  - client: `sn_client.h` (`sn_client_init`, `sn_client_take_control`,
    `sn_client_input`, `sn_client_tick`, `sn_client_send_app`);
  - keys: `sn_kdf.h` (`sn_derive_kdev`, `sn_provision_kdev`);
  - OS services: `port/shieldnet_os.h`.
- `README.md`: how ShieldNet works, adding the library to a build, the port
  seams, integrator obligations, and porting the command core.
- `shieldnet.cmake`: the source lists to compile.
- `examples/led_device.c` and `examples/led_client.c`: complete, commented
  programs for the two roles; copy their structure.
- The documentation site's API reference (`api/`, and `llms-full.txt`) is
  generated from the headers by `docs/hooks/api_reference.py`, so a header
  comment is the documentation: keep it accurate when you change a call.
- `host/sn_host.c` (a device) and `host/sn_client_host.c` (a blocking client)
  are small complete programs over real UDP.
- The protocol: [shieldnet-protocol](https://github.com/shieldled/shieldnet-protocol),
  `spec/transport.md`, `spec/message-layer.md` and `spec/application.md`. The
  `§N` numbers in the sources are those of its `design/transport.md`.

## Rules that matter

1. **A device never stores the PSK.** It holds `k_dev` with its `device_id`
   and starts with `sn_device_init_kdev`, checking for -1. A device handed the
   PSK once derives `k_dev` with `sn_provision_kdev` and erases every other copy.
   `sn_derive_kdev` is for clients and tools.
2. **The client owns no thread, socket, lock or clock.** Feed datagrams to
   `sn_client_input` and time to `sn_client_tick`, and serialise every
   `sn_client_*` call on one client yourself.
3. **The command core never allocates and never locks.** Each
   `shieldnet_device_ops_t` callback locks inside itself; a NULL callback makes
   the core answer the commands that need it `ERR_UNKNOWN_KIND`.
4. **Overridable constants** (`SHIELDNET_MAX_RESPONSE_BODY`, `SN_PENDING_TTL_MS`,
   `SN_PENDING_SLOTS`, `SN_WIRE_MTU`) are set on the compile target, identically
   for every translation unit, never with a `#define` in one file.
5. **No platform headers** in `src/` or `include/shieldnet/`: FreeRTOS, ESP-IDF,
   POSIX and Win32 code goes in `port/`.
6. **Wire compatibility is byte-exact** with goshieldnet v1. The test vectors in
   `test/sn_vectors.h` are generated by `test/gen_sn_vectors.py` from the spec
   repository's `vectors/`; regenerate, never hand-edit.

## Changing the library

```sh
cmake -S . -B build && cmake --build build                  # libraries + link checks
cmake -S test/sn -B build/test && cmake --build build/test && ctest --test-dir build/test
ci/build-and-test.sh plain     # the CI job; modes: plain asan constants
```

- A new source file goes in the right list in `shieldnet.cmake`; the link checks
  (`shieldnet_link_check`, `shieldnet_client_link_check`) catch an omission.
- `vendor/` is third-party (LZ4, and a modified KCP whose changes are listed in
  `vendor/ikcp.h`); keep changes there minimal and listed.
- The ESP-IDF benchmark apps in `bench/` build with `idf.py` and use the same
  sources; keep them building (`ci/build-esp32.sh`). Keep the Windows build
  working too (`ci/cross-windows.sh`, MinGW-w64).
- Every new file starts with the licence header:
  `/* Copyright (c) 2025-2026 BlackShield LDA` and
  ` * SPDX-License-Identifier: Apache-2.0 */` (or the same two lines as `#`
  comments).
- Record user-visible changes in `CHANGELOG.md`.
